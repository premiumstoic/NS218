# Feature Refinements & Additions Plan

This document outlines potential enhancements for the NS218 Interactive Class Playground, categorized into **UI/UX Refinements** and **Feature Additions**. 

## User Review Required
Please review the proposed enhancements. Let me know which features or UI polish you would like to prioritize for implementation. We can tackle them one by one or in related groups.

## Proposed Changes

### 1. UI/UX Refinements

#### Dark Mode Toggle
- **Goal**: Implement a light/dark mode switch.
- **Approach**: 
  - Update `globals.css` to include a standard CSS variable scheme (e.g., `--bg-color`, `--text-color`) and a `.dark` class or `@media (prefers-color-scheme: dark)` handler.
  - Create a `<ThemeToggle />` component in `components/layout/` to persist the user's preference in `localStorage`.

#### Rich Text Editor
- **Goal**: Replace basic `<textarea>` elements in discussions and notes.
- **Approach**:
  - Integrate a lightweight rich-text editor library (e.g., TipTap).
  - Update the `CommentForm` and teacher content creation forms to use the new component.
  - Ensure the rendered output securely handles HTML/Markdown using a sanitizer.

#### Micro-Animations
- **Goal**: Improve interactivity feel.
- **Approach**:
  - Add CSS transitions in `globals.css` for button hovers (`transform: scale(1.02)`).
  - Implement a 3D flip animation for the `<Flashcard />` component instead of an instantaneous swap.
  - Add entry animations for list items and quiz feedback using basic Framer Motion or CSS `@keyframes`.

### 2. Feature Additions

#### Student Progress Tracking
- **Goal**: Visually show completion rates per week.
- **Approach**:
  - **Database**: Add a `student_progress` table tracking `user_id`, `week_id`, and an array of completed `content_item_id`s.
  - **Backend**: Create an API route `POST /api/progress` to mark items as complete.
  - **Frontend**: Add a progress bar (e.g., `<progress max="100" value="75">`) to the weekly overview pages.

#### Teacher Analytics Dashboard
- **Goal**: Provide metrics on student engagement and quiz success rates.
- **Approach**:
  - **Database SQL Views**: Create Postgres views aggregating average scores per `quiz_question` from the `quiz_attempts` table.
  - **Backend**: Create a protected `GET /api/teacher/analytics` route.
  - **Frontend**: Build an `app/teacher/analytics/page.tsx` displaying simple bar charts or tables of the aggregated data.

#### Notification System
- **Goal**: Alert students of new weeks or replies.
- **Approach**:
  - **Database**: Add a `notifications` table (`id`, `user_id`, `message`, `link`, `is_read`, `created_at`).
  - **Backend**: Add logic to trigger inserts into this table when a teacher publishes a week or replies to a comment.
  - **Frontend**: Create a `<NotificationBell />` in the layout header that fetches and displays unread notifications.

## Verification Plan

### Automated Tests
- Once a specific feature is selected, we will outline the necessary integration flow tests (e.g., using Vitest or browser testing).

### Manual Verification
- Visual inspection of UI elements (Dark Mode, Animations).
- DB state validation after interacting with new features (Progress Tracking inserts, Analytics data accuracy).
